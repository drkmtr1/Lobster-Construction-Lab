## Enforcement assessment

- Native Windows Job Object process and job time termination limits account for user-mode CPU only. A kernel-held user-mode cap of the same numeric value permits additional kernel-mode CPU and therefore does not establish the authorized combined limit. [Windows Job Object time limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information)
- Windows process and job accounting supplies distinct user and kernel CPU counters. A watchdog sampling their sum and initiating termination can observe or react to a breach. The documented APIs provide no upper bound on the interval before the watcher is scheduled, and cross-process termination is asynchronous. This is insufficient to establish the hard total-CPU ceiling under the authorization. Cooperative checks in the frozen Budget cannot supply the required outside-worker protection. [Process times](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes) · [Job accounting](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information) · [Process termination](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess)
- Job CPU hard-rate mode limits cycles within scheduling intervals. Windows documents no exact conversion from these cycle budgets to cumulative user-plus-kernel process CPU seconds for this host. A rate limit cannot substitute for the authorized cumulative timer. [Windows Job CPU rate control](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_cpu_rate_control_information) · [Windows cycle accounting](https://learn.microsoft.com/en-us/windows/win32/api/realtimeapiset/nf-realtimeapiset-querythreadcycletime)

The frozen Win32 interpreter has no POSIX resource module. No installation, reserved host facility or system configuration change was used.

The missing combined CPU cutoff is sufficient to deny admission independently of any prospective wall-time implementation.
