# D204 revised native Windows execution contract — proposal v1

**Owner review required.** This is a separate execution-control proposal with no launch entry, supervisor implementation or approval. The accepted D204 execution gate stopped before launch. The proposal preserves all scientific code, registered cut and rank classes, chronological phase rules and numerical ceilings. A future execution requires a fresh run identity, specific runtime and supervisor bindings, separate Owner permission to use this revised policy, and qualification before opening D204. ## Policy comparison

| Dimension | Accepted original gate | Proposed Windows policy |
| --- | --- | --- |
| Total process CPU | Required an outside-worker hard cutoff on combined user and kernel CPU | Native user-mode Job time termination, outside-worker sampling of combined CPU and early stops, then mandatory final measured reconciliation |
| Elapsed wall | Required hard outside-worker ceiling | Suspend-inclusive sampled elapsed supervision, early stops, and measured terminal acceptance |
| Scientific counters and upper limits | Exact accepted tables | Same logical counters and maximum numerical CPU, elapsed, worker, and evidence ceilings |
| Success criteria | Authorized phase admissions and exact verification or exhaustion | Same scientific criteria plus complete cleanup, resource, and custody receipts |
| Authorization | Original attempt closed at admission | Fresh identity and new explicit approval, after non-scientific qualification |

Sampling and asynchronous shutdown leave a possible interval during which the worker runs after an intended stop. Windows user-time Job enforcement does not limit kernel-mode CPU. A Job CPU rate limit governs cycle scheduling intervals and does not meter cumulative combined CPU seconds. The reserves below are proposed margins, not bounds on scheduler delay, kernel accounting, system suspend, I/O completion or termination. A run crossing a measured maximum, even during cleanup, cannot be accepted as compliant. ## Sampled watchdog and termination

Use GetProcessTimes on the retained worker handle with separated user and kernel tick counts and GetTickCount64 for the observation timestamp and elapsed interval. Preserve integer ticks for CPU and integer milliseconds for elapsed comparisons. Also capture Job cumulative user/kernel/process counts at start and terminal reconciliation. The Job uses terminate-at-end-of-job for user time, without notification-only mode. User-time termination is native and periodically enforced; its threshold does not substitute for the two-component meter. [Process accounting](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes) · [Job accounting](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information) · [Job end action](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_end_of_job_time_information)

A dedicated watchdog loop in the external supervisor targets a 250 ms cadence without blocking on evidence I/O. Between samples it may wait briefly for the retained process handle, but every elapsed decision uses the measured GetTickCount64 clock, not a wait's relative timeout. Charge sleep and hibernation elapsed on resumption. An observation gap greater than 2,000 ms from phase start through observed process exit, accounting failure, negative or regressing counters, or an unreliable identity causes a stop and prevents compliant acceptance. A reboot, suspended observer or a long scheduling gap can invalidate a run even when the worker's scientific result exists. Keep first, last, maxima, maximum observed interval, counts, first stop cause and bounded summary records. Preserve the actual samples immediately before stop or exit. These records and the later qualification describe observed behavior only. [Windows elapsed accounting](https://learn.microsoft.com/en-us/windows/win32/sysinfo/interrupt-time) · [Windows elapsed clock](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-gettickcount64) · [Relative wait semantics](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject)

Request early stop if combined CPU reaches the original CPU ceiling minus 60 seconds or elapsed reaches the original wall ceiling minus 60 seconds. These are operational stop triggers. After natural worker exit following any applicable verification, or at the first supervisor stop, close off candidate continuation. An engine CANDIDATE by itself is not the end of the phase. On stop request TerminateJobObject with a distinct recorded reason. Wait on the retained worker handle, obtain exit code and terminal GetProcessTimes while it is valid, then release process/thread references before checking final Job accounting and zero active members. Use a bounded 10-second observed cleanup grace. Retain the Job handle through accounting and close it finally. Cleanup time remains charged to elapsed acceptance and does not extend either phase budget. Unexpected persistence or unresolved cleanup denies acceptance and prevents another phase. If the supervisor exits abnormally, kill-on-close is a backstop for members; the lack of verified exit and terminal receipts still prevents a scientific acceptance. [Windows Job termination](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject) · [Asynchronous process termination](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess) · [Job active-process accounting](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information)

## Terminal resource reconciliation and control states

Require both terminal process and cumulative Job user/kernel readings, valid start/end elapsed samples, verified exit, zero active members and lifetime Job process count one. Individual terminal counters must be monotone and reconcile with the observations and phase identity. Preserve both component readings and use the larger complete combined total against the CPU ceiling. Record accounting differences and reject unresolved inconsistency, any missing measurement or a resource breach. Compare elapsed through cleanup against the full approved elapsed ceiling in measured milliseconds. The elapsed representation is not the precision of physical time. No measured breach, early watchdog stop, missing interval, bad exit, evidence denial or incomplete cleanup is compliant, even if a scientific artifact exists. Retain such an artifact separately with exact failure context.

The frozen numerical phase logic governs any later approved worker:

- Primary CANDIDATE arrives as a bounded framed input to the supervisor. Before allowing in-process verification, preserve its exact payload and receipt durably and acknowledge that write. Keep the same phase Job and clocks across raw candidate, approval to verify and applicable frozen independent 41/48 verification. No duplicate test targets or rank-specific campaign.
- A verified and resource-compliant primary positive stops. Verification failure, INCOMPLETE, interruption or any noncompliant resource status stops without an accepted scientific disposition. Preserve raw facts. Only valid, fully reconciled primary EXHAUSTED permits the distinct independent audit phase, with proof of no active earlier worker before creating the next Job.
- Audit EXHAUSTED requires the same complete controls and the retained primary exhaustion for a registered negative. An audit candidate after primary exhaustion is independently verified within the audit phase; preserve both receipts and report the discrepancy. An incomplete or unqualified audit leaves the registered question unresolved. No automatic re-entry, retry, resume, escalation or alternate control profile.

## Evidence byte controls and unchanged caps

Redirect unintended output to a bounded diagnostic path or discard it, with no unbounded capture file. Validate names, schema and payload framing; archive raw candidate bytes under exclusive creation and sync before acknowledgement. Count every artifact, snapshot, journal, temporary write and duplicate evidence copy in the planned publication pipeline before its write. ## Outstanding qualification and Owner decision

This proposal does not satisfy the prior strict instantaneous external combined CPU cutoff requirement and does not change the verdict of the original gate. Before any future D204 launch, implement and freeze the supervisor under separate authorization, verify live executable/source bindings and actual native controls in the real host job context, and independently qualify with bounded non-scientific process probes. Cover atomic at-creation assignment and crash cleanup, pre-resume membership, user-limit and wall stop, elapsed behavior across observer gaps, final accounting, child refusal, interruption and verified cleanup, and pre-write rejection at the byte cap. A finite probe cannot prove a worst-case latency bound. Exact proposed margins and observed acceptance terms need explicit Owner approval. A fresh scientific run additionally requires its own gate, new approval and the unchanged scientific contract. No environment is admitted by this preparation.
