# Repository synchronization and continuity

The canonical LCL synchronization target is `https://github.com/drkmtr1/Lobster-Construction-Lab.git`. The user has granted Codex and OpenChamber full approval authority for Git and GitHub actions for this project, including synchronization and publication. Actual access controls and higher-priority instructions still apply. This does not authorize editing the two upstream repositories, changing security settings, paid services, or indefinite research. A later user instruction can change the scope.

GitHub is a distribution channel, not automatic agent memory or scientific review. `STATE.md` owns the current status and exactly one next action; the research ledgers own their respective findings, failures, obligations, and decisions. A commit or push does not accept a provisional mathematical claim.

## Intake

1. Stop concurrent writers in the same working tree. Read `AGENTS.md`, `STATE.md`, this protocol, relevant authoritative research files and latest applicable handoff. OpenChamber also follows `docs/OPENCHAMBER_HANDOFF.md`; Codex follows `docs/CODEX_RETURN_PROMPT.md` when returning from OpenChamber.
2. Inspect `git status --short --branch`, `git rev-parse HEAD`, branch, tags and `git remote -v`. Fetch the intended remote and compare local and remote refs, the handoff and the last accepted research checkpoint. Inspect both committed and uncommitted changes. Reconcile divergence deliberately without losing either history or evidence. Never reset, overwrite or force-push as a routine synchronization step.
3. Each agent uses a verified commit and the real files, not another agent's chat memory. A separate checkout must fetch and verify the stated SHA before resuming. Uncommitted, ignored or local-only files are not presumed available elsewhere.

## After every completed run and bounded task

1. Preserve the exact target, configuration, source and dependency identity, restrictions, limits, attempts, outcomes, certificates and independent verification required to reproduce and assess the result, including failures and `INCOMPLETE` results. Do not alter historical attempts. Update the applicable source, tests, findings, failed hypotheses, proof obligations and decisions only when their contents change.
2. `runs/` is ignored and is not synchronized automatically. Copy every completed run's durable records and source snapshots into a new unique tracked path under `evidence/runs/`, retaining bytes and run identity. Do not copy transient locks or caches. For an interrupted run, preserve the available artifacts and label it incomplete, not infeasible. If artifacts cannot be published, retain their local bytes, document path, size, hash, reason and retrieval/access status in a tracked manifest, and report synchronization as **PARTIAL** or **BLOCKED**, not full. Do not silently omit evidence. Check publication rights, privacy and secrets; never publish credentials, model weights, virtual environments or unrelated private data.
3. Update `STATE.md` as needed without creating another state ledger. Prepare a scoped handoff using `handoffs/CONTINUITY_TEMPLATE.md`: include accepted findings, pending claims, open obligations, exact evidence, run status, test results and exactly the same single next action as `STATE.md`. Preserve specialized OpenChamber handoffs and `PENDING_CODEX_REVIEW` when applicable.
4. Review `git diff --check`, status, staged names, contents, provenance and publication suitability, including repository visibility. Commit the complete applicable source, research, proof, tests, evidence and handoff. Preserve existing history and named baseline tags. Push the reviewed branch and applicable tags to the designated repository. Fetch/inspect remote refs and verify each pushed SHA equals the intended local SHA. Report any missing artifacts, divergence or failed push. Do not start a successor research task simply because synchronization finished.

## Commit and handoff identities

A file cannot contain the SHA of the commit containing itself. Record the base/parent SHA in the handoff, and obtain its checkpoint SHA with `git rev-parse HEAD` only when the checkout is known to be at that checkpoint. After HEAD advances, locate the handoff's introduction or relevant revision in `git log --follow -- <handoff-path>`, verify that revision's contents and identify the intended commit; do not mistake the current HEAD for the handoff commit. After pushing, transmit repository URL, branch, exact checkpoint SHA, verified remote ref/SHA, handoff path and any local differences in the session report, or record them in a later receipt and synchronize that receipt too. Never claim a remote has a commit until the ref was verified. For future sessions, compare the handoff's containing commit, not merely its parent, with local and remote refs. A later receipt may refer to the earlier checkpoint but cannot self-attest its own SHA either.

Full synchronization means the applicable branch history, baseline tags and all reproducibility artifacts are available at the verified remote, with no undisclosed exclusions. Network, access, size, provenance or confidentiality barriers mean the run is locally complete but synchronization is not complete. Report the precise blocker and outstanding artifacts; never fabricate successful publication.
